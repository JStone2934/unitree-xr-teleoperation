# 手柄按键映射计划

本文档描述将终端键盘快捷键（`r` / `s` / `t` / `q` / `p`）映射到 PICO 手柄按钮的设计方案，供实现与测试参考。

**适用场景**：`teleop_hand_and_arm.py` 以 `--input-mode controller` 启动（参见 [站桩遥操作.md](./站桩遥操作.md)）。

**状态**：已实现（`teleop/teleop_hand_and_arm.py`，`--input-mode controller` 默认启用手柄映射；可用 `--no-controller-shortcuts` 关闭）。

---

## 1. 目标

- 操作员佩戴头显后，**无需切回 SSH 终端**即可完成：开始遥操、开始/停止录制、拉回 G1 数据、安全退出。
- 与现有 **键盘**、**IPC**（`--ipc`）控制并存，行为一致。
- 不改变扳机/侧握/摇杆对末端执行器与运控的既有用途。

---

## 2. 现状（实现前）

| 功能 | 键盘 | 手柄（当前代码） |
|------|------|------------------|
| **r** 开始遥操 | ✅ | ❌ 等待 `START` 阶段不读手柄 |
| **q** 退出 | ✅ | ⚠️ 仅右手 A，且为电平触发（按住每帧触发） |
| **s** 开始录制 | ✅ | ❌ |
| **t** 停止并保存 | ✅ | ❌ |
| **p** 拉回 G1 episode | ✅ | ❌ |

**已占用手柄输入**（不可复用）：

| 输入 | 用途 | 条件 |
|------|------|------|
| 扳机 Trigger | Dex3 / Dex1 夹爪开合 | `controller` + 对应 `--ee` |
| 侧握 Squeeze | `dex3_true` 捏合 | `controller` + `dex3_true` |
| 右手 A | 退出（等同 q） | `controller` |
| 左/右摇杆按下 | 软急停 `Damp()` | `controller` + `--motion` |
| 左/右摇杆轴 | 行走 / 转向 | `controller` + `--motion` |

TeleVuer 已暴露但未用于高层控制：`left/right_ctrl_bButton`、`left_ctrl_aButton` 等。

## 3. 按键方案（已定）

与 [README_zh-CN.md](./README_zh-CN.md) 习惯一致：**右手 A = 退出**；录制开始/停止分键，避免与文档中「单键 s 切换」和代码中 **s / t 分离** 不一致。

| 功能 | 键盘（保留） | 手柄映射 | 触发方式 |
|------|-------------|----------|----------|
| **r** 开始遥操 | `r` | **左手 A（X）** | 上升沿（按下瞬间） |
| **q** 安全退出 | `q` | **右手 A** | 上升沿（改进现有电平逻辑） |
| **s** 开始录制 | `s` | **右手 B** | 短按：松开时若按住时间 **&lt; 2s** |
| **t** 停止并保存 | `t` | **左手 B（Y）** | 上升沿 |
| **p** 拉回 G1 episode | `p` | **右手 B** | **长按 ≥ 2s**（见下节） |

### 3.1 右手 B：短按 s / 长按 p

右手 B 同时承担「开始录制」与「拉回数据」，通过**按住时长**区分：

```text
按下右手 B
    │
    ├─ 持续按住 ≥ 2.0s  → 触发 p（RECORD_TRANSFER_REQUEST），标记本周期为「长按已处理」
    │
    └─ 松开且按住 < 2.0s 且未触发过长按  → 触发 s（RECORD_START_REQUEST）
```

**规则**：

- 长按阈值：**2.0 秒**（常量 `CONTROLLER_RIGHT_B_LONG_PRESS_S = 2.0`，便于后续 CLI 可调）。
- 长按 **p** 在达到 2s 时**立即触发一次**，不等待松开。
- 若已触发长按 **p**，松开时**不再**触发短按 **s**。
- **s** / **p** 仍遵守现有前置条件（例如须已按 **r** 进入 `START`；**p** 在录制中会被 Record Guard 忽略等）。

### 3.2 `--motion` 模式下的并存关系

| 手柄操作 | 功能 |
|----------|------|
| 左手 A | 开始遥操（r） |
| 右手 A | 退出（q） |
| 右手 B 短按 | 开始录制（s） |
| 右手 B 长按 2s | 拉回 episode（p） |
| 左手 B | 停止录制（t） |
| 左摇杆按下 + 右摇杆按下 | 软急停（不变） |
| 摇杆推动 | 行走 / 转向（不变） |

AB 键与扳机、摇杆键物理分离，一般无冲突。

## 4. 架构设计

### 4.1 统一动作入口

将 `on_press(key)` 中的逻辑抽取为单一函数，例如：

```text
request_teleop_action(action, source="keyboard"|"controller")
    action ∈ { "start", "stop", "record_start", "record_stop", "record_transfer" }
```

- **键盘**：`on_press` 仅做 `key → action` 映射。
- **IPC**：`IPC_Server.cmd_map` 仍映射到同一 `on_press` 或直连 `request_teleop_action`。
- **手柄**：边沿/长按检测后调用 `request_teleop_action`。

### 4.2 边沿与长按状态机

- 维护上一帧按钮状态（建议挂在 `tv_wrapper._controller_btn_state` 或模块级结构体）。
- **上升沿**：`pressed and not prev_pressed` → 可用于左手 A/B、右手 A。
- **右手 B**：单独状态机
  - `right_b_pressed_at`：按下时刻（`None` 表示未按）
  - `right_b_long_press_fired`：本按下周期是否已触发 p

主循环频率约 `--frequency`（默认 30Hz），2s 长按约 60 帧，精度足够。

### 4.3 两处轮询

| 阶段 | 代码位置（约） | 行为 |
|------|----------------|------|
| 等待开始遥操 | `while not START and not STOP` | `controller` 模式下每帧 `get_tele_data()`，检测左手 A → start、右手 A → stop |
| 主遥操循环 | `tele_data` 获取后的 high-level 块 | 检测 s/t/p/q 映射；替换现有右手 A 电平判断为上升沿 |

### 4.4 开关策略

建议：

- `--input-mode controller` 时**默认启用手柄快捷键**；
- 可选 `--no-controller-shortcuts` 仅保留键盘/IPC（无头调试时用）；
- **不**默认关闭键盘，`sshkeyboard` 与手柄双通道并存。

## 6. 测试计划

| 场景 | 检查点 |
|------|--------|
| 仿真 `--sim --record --input-mode controller` | 左手 A 进入跟踪；右手 B 短按 s、长按 2s 为 p；左手 B 为 t |
| 右手 B 按住 1.5s 松开 | 只触发 s，不触发 p |
| 右手 B 按住 ≥2s | 只触发 p，松开后不触发 s |
| 未按 r 就按右手 B | 与键盘一致：s 被忽略或 warning |
| 长按右手 A | 只触发一次 q |
| `--motion` | 双摇杆急停、摇杆行走仍正常 |
| 键盘 r/s/t/q/p | 与手柄并行可用 |
| G1 `--record-backend g1` | 长按 p 能排队 transfer |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 想录 s 却误长按成 p | 日志区分 `[Controller] right B short/long`；操作员熟悉 2s 阈值 |
| 录制中误触右手 B | 现有 Record Guard；可选录制中忽略 s |
| 等待阶段未戴头显 | 保留键盘 r/q |
| 文档写「s 切换录制」 | 统一为 **s 开始、t 停止** + 本表手柄映射 |
